# AlmaLinux 9候補のQtPdf告知・配布ソース確認

2026-11-12。revision3は保持し、新規専用資料ディレクトリで確認した。公開・コミット・タグ・元作業ツリーの版変更は行っていない。

## QtPdf告知の具体的な照合

Qtランタイムの自己申告は6.11.2、x86_64、shared/dynamic、release、GCC 11.5.0。PySide設定にはビルド日時2026-08-14とPdfを含むビルド済みモジュール一覧がある。これは自己申告・設定資料であり、独立したビルド再現の証明ではない。

実QtPdfバイナリはrevision3内と一致し、Chromium partition allocatorのソースパス文字列がある。wheel内のファイル名をcredits/license/sbom/args.gnで検索した範囲では、生成creditsやGN設定は見つからなかった。全配布先に存在しないという主張ではない。

[Qt PDF公式ライセンス文書](https://doc.qt.io/qt-6.11/qtpdf-licensing.html)が挙げるAbseil、FreeType、PDFium、Chromium、fast_float、ICU、libjpeg-turbo、libpng、zlibの9群について、Qt 6.11.2ソース由来の対応文書がrevision3の`Qt-source-notices`本文にあることを全群確認した。参照したライブ文書は現在6.11.3表記のため、正確な6.11.2のバイナリ構成表とは扱わず、成分名のクロスチェックに用いた。

各群の実パス・サイズ・ハッシュと候補内存在確認、Qt構成情報は[QtPdf照合JSON](linux-almalinux9-qtpdf-coverage-review-2026-11-12.json)に保存した。これで「QtPdf告知があるはず」という未確認状態を解消したが、正確な内包選択・過去の変更パッチ・コンパイラー設定の全証明とは区別する。

## 配布ソースZIPの検査

revision3対応ソースZIPを新規専用ディレクトリへ安全性確認後に展開し、全683入力のハッシュをZIP内目録と照合した。GitディレクトリがなくてもSOURCE-MANIFEST.jsonからビルド入力を取得でき、Alma RPMの`--check`はrevision3の正しい出力名を返した。

関連テストは初回1件失敗・14件成功・9サブテスト成功。ZIPには実際のInstalled-packages.txtが収録されるため、未同梱を前提としたsource-runテストが実環境の告知を読んでしまうことが原因だった。

`tests/test_license_info.py`の当該テストを一時ライセンスディレクトリで実行するよう修正し、開発ツリーと配布ソースに依存しない入力へ分離した。アプリコード・告知の動作は変更していない。新規展開コピーへテストだけを反映した結果、15テスト・9サブテストとruffが成功した。元テストは別ファイルに保持し、ZIPそのものは変更していない。

[ソース検証JSON](linux-almalinux9-source-archive-review-2026-11-12.json)へ初回失敗、修正範囲、ZIPハッシュ、事前検査・再実行結果を保存した。修正済みテストは元作業ツリーと展開検証コピーにあり、既存revision3のZIPには未反映である。最終ソース確定時に同期が必要。
